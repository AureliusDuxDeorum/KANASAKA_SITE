Security

How KANASAKA protects KS_Link messages and kanasaka.com accounts, and how to report a problem.

KS_Link messages

Messages are encrypted on the sending device, using per-conversation keys derived from each participant's device keys, before they reach KANASAKA's relay server. Images use the same encrypted channel as text.

The relay stores and forwards encrypted payloads, conversation membership and delivery metadata such as timestamps and delivery acknowledgements. It has no access to message content.

  • KS_Link accounts are separate from kanasaka.com accounts: no shared login, database or subscription.
  • Two-factor authentication (TOTP) with backup codes, and a session list to see and revoke every signed-in device.
  • Plugins run in a WASM sandbox with explicit, revocable permissions. KS_Social content is not end-to-end encrypted by design, because it is meant to be visible to your contacts.

KS_Link is alpha software. Features and the protocol may change between releases. Full details are in the technical overview.

kanasaka.com accounts

  • Passwords are hashed with Argon2id and checked against a policy that blocks short and common passwords.
  • Sessions use Secure, HttpOnly, SameSite=Strict cookies, are rotated regularly and are revoked on sign-in, password change and when two-factor authentication is switched off.
  • Email verification is required before an account can sign in. Sign-in attempts, verification codes and message-sending endpoints are rate limited.
  • Two-factor authentication with one-time codes and backup codes is available, and it is required for administrative access.
  • The site is served over HTTPS only and uses a strict Content Security Policy that does not allow inline or third-party scripts.

Report a vulnerability

Send reports to contactns@kanasaka.com. We typically respond within one to two business days. Our machine-readable contact details are in security.txt.

Please include enough detail to reproduce the issue and avoid accessing data that is not yours.
