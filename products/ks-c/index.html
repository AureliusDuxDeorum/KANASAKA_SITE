KS_C Beta

A coding agent for your own models. It plans, edits, runs and checks your project on Windows and Linux, and asks before it acts.

Download Technical overview

What it is

A full coding toolset on the model you choose

KS_C does not come with a model and does not route your code through KANASAKA. You point it at an endpoint you already have, and it brings the tools.

  • Bring your own endpoint

    Run it on a local model server such as Ollama, LM Studio or any OpenAI-compatible server, or on a cloud provider: Anthropic, OpenAI, Gemini, OpenRouter, Groq, DeepSeek or Mistral. Local or cloud, the tools work the same. You can change a provider's address, and add your own.

  • Five modes

    Chat answers questions about the project and changes nothing. Plan reads the project and drafts a plan and to-do list. Code works the list one item at a time and pauses after each. Auto works the whole list. Security audits the project, fixes the gaps and re-checks.

  • The tools a modern agent needs

    Read, list, glob, grep, edit and write files; run commands and background processes such as dev servers; fetch web pages; and use GitHub and Blender through built-in plugins. Any MCP server you add brings its tools too. A UI verifier renders your app and compares it with a reference screenshot.

  • You approve what it does

    Writes, commands and web fetches ask first, and writes show a diff. A command that reaches outside the project always asks, with the exact command shown. Every edit is snapshotted, so you can undo one edit or rewind everything since a message.

  • A sandbox where one exists

    On Linux, commands run in a bubblewrap sandbox: read-only system, only the project writable, your keys and browser profiles hidden, no network apart from plain install commands. The header says SANDBOXED or NO SANDBOX, and without a sandbox every command asks.

  • Your keys stay on your machine

    Provider keys live in the operating system's keychain, never in a file. Requests to a model go only to the hosts you configured. Credential files such as dotenv files, private keys and .ssh are refused by the agent. Text from files, commands, web pages and MCP servers is marked untrusted to the model.

  • One KANASAKA account

    KS_C opens with a KANASAKA account. You sign in, register and reset your password inside the app, and the app talks to kanasaka.com directly. Each device gets its own session, listed in the app's Settings, where you can sign any of them out. Your code, prompts and provider keys are not sent to KANASAKA.

  • Built for long sessions

    A message queue, a command palette (Ctrl+K), a Changes tab with git status and diffs, task rename and delete, a usage and cost ledger, an optional spend limit per run, and project instructions in AGENTS.md or custom slash commands in .ksc1/commands.

Availability

Platforms

Windows
x64 installer · Windows 10/11, 64-bit · no command sandbox, and command support is limited
Linux
.deb, .rpm and AppImage · Debian/Ubuntu, Fedora/RHEL or any distribution · install bubblewrap for the command sandbox
macOS
Not available yet
Your model
An endpoint you provide: a local server or a cloud provider with your own key. KS_C does not include model access.

Beta software

KS_C is under active development. An agent can make mistakes and a model can be steered by text it reads, so review what it proposes before you approve it. See the Privacy Policy for how KS_C handles your data and the Terms of Service for the terms that apply to it.
